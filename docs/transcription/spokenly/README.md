## Keyboard Activation Semantics

MacBook Fn is the only active keyboard shortcut:

| Input | Result |
| --- | --- |
| MacBook Fn held while speaking | Spokenly records with push-to-talk and stops on release |

Trackpad, Magic Mouse, and MX Master toggles enter Spokenly through the same
background helper. MacBook Fn remains a separate direct Spokenly control for
push-to-talk. The Ducky hardware Fn key is firmware-only and is not exposed to
macOS, so it cannot use this shortcut.

Standalone Right Option is not a Spokenly toggle. It remains a native modifier
in keyboard chords, and no repository-level standalone Right Option mechanism
is configured.

## Live Preference Representation

The current profile is stored in `modes.v2` inside:

```text
~/Library/Preferences/app.spokenly.plist
```

`modes.v2` is JSON stored as plist data. Its shortcut-relevant shape is:

```json
{
  "name": "Default Mode",
  "id": "00000000-0000-4000-8000-000000000001",
  "modeMac": "autoInsert",
  "shortcut": {
    "id": "00000000-0000-4000-8000-000000000001",
    "activationMode": "pushToTalk",
    "trigger": {
      "keys": {
        "_0": {
          "rawFlags": 8388608
        }
      }
    }
  }
}
```

`rawFlags: 8388608` is the live serialization of the Fn modifier trigger.
Prefer Spokenly's settings UI when changing it instead of treating this private
encoding as a stable public API.

## Current Device Compatibility

Spokenly rejects synthetic Right Option events generated by Logitech and BTT,
so every hands-free input uses the documented toggle deeplink through
`Spokenly Toggle.app`. MacBook Fn uses Spokenly's direct push-to-talk shortcut.
No standalone Right Option route is configured.

| Device | Physical input | Current adapter | Toggle behavior | Hold or chord behavior |
| --- | --- | --- | --- | --- |
| MacBook trackpad | 3-finger tap | BTT opens `Spokenly Toggle.app`, which calls `spokenly://toggle` | Hands-free toggle | Discrete gesture; no hold behavior |
| MX Master 3S | Auxiliary/thumb button `c195` | Logitech Smart Action opens `Spokenly Toggle.app`, which calls `spokenly://toggle` | Hands-free toggle | Discrete button action; no hold behavior |
| Magic Mouse | TipTap Left, 1 Finger Fix | BTT opens `Spokenly Toggle.app`, which calls `spokenly://toggle` | Hands-free toggle | Discrete gesture; no hold behavior |
| MacBook keyboard | Physical Fn | Direct Spokenly shortcut | Not a toggle | Hold for push-to-talk; release stops recording |

### MX Master Hands-Free Adapter

The MX Master uses Logitech slot `mx-master-3s-2b034_c195`. In every current
Logitech profile, that slot references the native Logitech Smart Action
`Spokenly Hands-Free`.

The Smart Action opens a background-only helper, which calls Spokenly's
documented toggle deeplink:

```text
MX Master c195
  -> Logitech Options+: Smart Action "Spokenly Hands-Free"
  -> ~/Applications/Spokenly Toggle.app
  -> spokenly://toggle
  -> Spokenly hands-free toggle
```

| Component | Value |
| --- | --- |
| Logitech Smart Action ID | `d18fe790-d754-4fbc-8e82-0e5df78bda9e` |
| Logitech action type | `OPEN_FILE_FOLDER`, open application |
| Helper application | `~/Applications/Spokenly Toggle.app` |
| Tracked helper source | `mac/.local/libexec/spokenly-toggle/` |
| Spokenly deeplink | `spokenly://toggle` |
| Spokenly setting changed | None |
| Verification status | Physical MX Master thumb-button test passed. Logitech recorded six Smart Action executions. |

Rebuild or reinstall the tracked helper with:

```text
~/.local/bin/install-spokenly-toggle-helper
```

The helper is a background-only application and does not appear in the Dock.
It changes no Spokenly preference. Its only action is to open the official
`spokenly://toggle` URL.

The former global F20-to-Right-Option BTT adapter
`1F6581F7-5158-4562-96BC-4651E63C893D` was removed after physical tests showed
that Logitech-generated F20 did not enter BTT's keyboard-trigger pipeline.
Another test used a modified middle-click plus BTT's high-level mouse-event
mode; BTT did not capture that event either. Direct BTT action tests produced
synthetic modifier events that Spokenly ignored. The later `Ctrl+Shift+B` BTT
adapter also failed because the thumb-button event never reached BTT. None of
these failed routes is part of the live setup. The current adapter avoids both
keyboard emulation and synthetic modifiers.

## Keyboard modifier ownership

The Ducky One 2 Command, Option, and Caps mappings are owned by native macOS
in `com.apple.keyboard.modifiermapping.1241-661-0`. No standalone Right Option
mechanism is configured, so Right Option remains a native modifier in keyboard
chords and does not toggle Spokenly by itself.

## Spokenly Automation Hooks

Spokenly exposes official deeplinks that may help later automation:

| Action | Deeplink |
| --- | --- |
| Start main mode | `spokenly://start` |
| Stop recording | `spokenly://stop` |
| Toggle recording | `spokenly://toggle` |
| Start a mode | `spokenly://start?mode_id=<id>` |
| Toggle a mode | `spokenly://toggle?mode_id=<id>` |
| Switch mode without recording | `spokenly://switch?mode_id=<id>` |
| Open keyboard controls | `spokenly://tab/shortcuts` |

Source: [Spokenly deeplink documentation](https://spokenly.app/docs/macos/deeplinks).

These deeplinks control recording and modes. The MX Master, trackpad, and Magic
Mouse routes use the documented toggle deeplink through the background helper.
The URL handler resolves to the installed Spokenly application without
foreground activation.

## Verification Checklist

1. Confirm Spokenly is running and idle.
2. Hold MacBook Fn, dictate a short phrase, and verify release stops
   push-to-talk.
3. Run MX Master start/stop and mixed-input combinations.
4. Test the trackpad 3-finger tap as a hands-free toggle.
5. Test the Magic Mouse TipTap Left gesture as a hands-free toggle.
6. Run one longer mixed-input dictation and verify the complete transcription
   survives when the other input stops it.
7. On the Ducky, verify the native Command, Option, and Caps mapping remains
   owned by macOS preference `com.apple.keyboard.modifiermapping.1241-661-0`.
8. Verify standalone Right Option does not toggle Spokenly and that a Right
   Option chord remains a native modifier chord.
9. Confirm browser middle click, Back, and Forward remain unaffected.
